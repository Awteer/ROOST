総 [kWh]／実際の完了 [分]：

- (5) はどの $T_{\max}$ でも最小．70 分の (5) は (2) にエネルギー（−33%）でも完了時刻でも勝つ．
- NCR がないと時間が厳しいとき往復が使えなくなる．NCR があると 70 分でも往復が残る．NCR は経路を縮めて時間の余裕を作り，その余裕を往復に回させる．
- 70 分の (5) では NCR が「枠」（出撃の連鎖 4 本，$S=L+1$）と「拠点」（往復 2 本）を同時に担う．
- 60・65 分は 900 秒で解も解なしの証明も得られず（たぶん解なし）．掃引の前に最短の完了時刻を求めるべき．

### 2.5 理論：時間の制約がないと出撃は要らない

- 往復ありで時間の上限がないと，最適解に出撃が 1 本もない．$T_{\max}$ を締めると出撃が戻る（(5) で 0→1→2→3→4 本）．
- 往復なしの最適解の出撃 25 本を，1 本ずつ発射点か回収点での往復に置き換えると，24 本でエネルギーが下がった．残る 1 本は +0.002 kWh で，ほぼ引き分け．
- 置き換えの式（$cd_{ijk}=out_{ij}+back_{jk}$，$\beta_P$ は出撃の間のトラックの道での積載 1 kg あたりのエネルギーの増分）：

$$\Delta_i=\big(back_{ji}-back_{jk}\big)+m_d\,\beta_P,\qquad \Delta_k=\big(out_{kj}-out_{ij}\big)+(m_d+q_j)\,\beta_P$$

- 出撃は「時間の装置」（走りながら飛ばす並列性），往復は「エネルギーの装置」．エネルギーから見た出撃の理由は「荷を積んだ往路に都合の良い点」と「空の復路に都合の良い点」がずれること．

## 4. 決まった設計

### 4.1 解の表し方 A：停車の列＋ドローン客ごとの配り方

```python
from __future__ import annotations
from dataclasses import dataclass, field


@dataclass(frozen=True)
class Stop:
    uid: int        # 停車ごとに固有（同じ NCR 地点に 2 回止まれば別の uid）
    kind: str       # "depot" | "customer" | "ncr"
    ref: int        # kind="customer" なら客の番号，"ncr" なら NCR 候補の地点の番号，"depot" なら 0


@dataclass(frozen=True)
class Loop:
    at: int         # 往復する停車の uid


@dataclass(frozen=True)
class Sortie:
    launch: int     # 発射する停車の uid
    retrieve: int   # 回収する停車の uid


@dataclass
class Solution:
    stops: list[Stop]                                   # トラックの停車の列（先頭・末尾はデポ）
    drone: dict[int, Loop | Sortie] = field(default_factory=dict)   # ドローン客 j → 配り方

    def pos(self) -> dict[int, int]:
        """uid → 列の中の位置．列を変えたら毎回引き直す．"""
        return {s.uid: p for p, s in enumerate(self.stops)}
```

- トラックの客は `stops` に，ドローンの客は `drone` の鍵に，ちょうど一方に 1 回だけ出る．
- 出撃・往復は位置ではなく `uid` で指す．停車を挿入しても指す先がずれず，同じ NCR 地点の再訪問も区別できる．
- 例（8.20.9.a，$T_{\max}$=70 分の (5) の最適解）：

| 位置 | uid | kind | ref |
|---|---|---|---|
| 0 | 0 | depot | 0 |
| 1 | 1 | customer | 5 |
| 2 | 2 | customer | 2 |
| 3 | 3 | ncr | 0 |
| 4 | 4 | depot | 0 |

```python
drone = {4: Sortie(0, 1), 8: Sortie(1, 2), 7: Sortie(2, 3), 1: Sortie(3, 4), 3: Loop(0), 6: Loop(3)}
```

- この形と形のチェック（§4.3）は 10/26 に小さく動かして確認済み（エラーなし．停車を途中に挿入すると「使われていない NCR」だけが出て，出撃の指す先はずれない）．

### 4.2 コピーの扱い

- ROOST にはコピーという概念がない．同じ NCR 地点への再訪問は，別の uid の停車として列に並ぶだけ．
- 地点ごとの最大訪問回数 $c$ をパラメータとして持つ．**既定は $c=\infty$**．MILP と突き合わせる検証では $c=1$（これまでの MILP の実験は全部 $c=1$）．
- 定式化（コピーの数 $c$ をパラメータに持つ (N1)–(N41)）とは，$c$ を揃えれば同じ解の集合．ROOST の表し方は位置で書く定式化 (S1)–(S12) の解そのもの．
- 比べるときは必ず $c$ を揃える．再訪問の効果は ROOST の中で $c=1$ と $c=2$ を比べて見る．

### 4.3 定式化と揃える条件（形のチェック）

| 定式化 | 中身 | ROOST での書き方 |
|---|---|---|
| — | 先頭と末尾はデポ | `stops[0]`，`stops[-1]` |
| — | 出撃は前から後ろ | `pos[launch] < pos[retrieve]` |
| (N24)–(N29) | 出撃どうしが重ならない | 区間 $[p,q]$ を並べ，次の発射 $\ge$ 前の回収（回収した停車でそのまま次を発射は可） |
| (N30) | 飛行中の停車では往復しない | 区間の内側 $p<x<q$ の停車での `Loop` は不可（トラックが止まること自体は可） |
| (N7) | 同じ地点のコピーどうしの弧は禁止 | 同じ NCR 地点の停車を連続して並べない |
| (N18) | 訪れた NCR は必ず使う | 発射・回収・往復のどれにも出てこない NCR の停車は不可 |
| A9 | デポ発・デポ着の出撃は禁止 | `Sortie(出発デポ, 帰着デポ)` は不可 |
| #17 | デポでの往復は出発デポだけ | 帰着デポでの `Loop` は不可 |
| A10 | 客の地点にも NCR を置ける | 候補の地点の集合に客の地点を含めてよい |
| — | 重い客はトラックだけ | `drone` の鍵に重い客がいない |
| A4 | 同じ NCR 地点は最大 $c$ 回 | 地点ごとの停車の数 $\le c$ |
| (N9)，MTZ | 対称性の除去，部分巡回の除去 | 不要（コピーがなく，列なので部分巡回は起きない） |

### 4.4 評価器（v1：毎回全部を評価し直す）

**前もって計算する表**（地点の通し番号：デポ 0，客 $1..n$，NCR 候補 $n+1..n+|R|$）

- トラックの走行時間 $\tau_{ab}$
- トラックのエネルギー：弧ごとに積載 $W$ の凸な区分線形 $\max(c_0,\ c_0+\alpha+\beta W)$（`Univ_Lab\04_実装\XIAO\ncr_milp\tables.py` と同じ式．`xiao/energy.py` を呼ぶ）
- ドローンの往路 $out_{aj}$・復路 $back_{ja}$ のエネルギーと時間（地点×客の 2 枚．出撃の 3 次元の表は作らない）
- 電池の可否：$out+back\le$ 電池

**手順**（列を前から 1 回なめる．`check.py` と同じ）

1. 出発デポ：積載の初期値＝トラックの客の荷物＋デポ以外から出るドローン客の荷物．出発時刻＝デポでの往復の時間の合計．デポで発射するなら帰着時刻を予約し，ドローンを機外にする．
2. 各停車 $p$：
   1. 到着時刻＝前の出発時刻＋$\tau$
   2. この弧のトラックのエネルギーを足す．質量は積載＋（ドローンが機上なら $m_d$）（A11）
   3. 回収があれば，ドローンの帰着時刻が到着より前ならエラー（**ドローンの先着は禁止**，決定ログ #8）．準備完了＝帰着時刻．ドローンを機上に戻す．回収がなければ準備完了＝到着時刻
   4. 客の停車なら荷物を降ろす
   5. 往復：ドローンが機上か確かめ，往復の時間を順に足し，荷物を降ろす
   6. 発射：ドローンが機上か確かめ，荷物を降ろし，帰着時刻を予約して機外にする．出発時刻＝準備完了
   7. 待ち＝出発時刻－到着時刻
3. 終わり：完了時刻＝帰着デポでの出発時刻．積載が 0 か，ドローンが機上か，電池，重い客，トラックの容量，§4.3 の形のチェック

**返すもの**：エネルギーの内訳，完了時刻，待ちの合計，停車ごとの到着・出発時刻と積載，エラーの一覧，探索で使う目的の値

$$f=E_{truck}+E_{drone}+\lambda\,\max\big(0,\ T-T_{\max}\big)$$

ROOST の解をコピーつきのノード番号に変換すれば `check.py` にも通せる（独立した二つ目の検算）．

### 5.1 オペレータの最初の版（叩き台）

| 種類 | 名前 | 中身 |
|---|---|---|
| 壊す | ランダム | 客を $k$ 人抜く |
| 壊す | 最悪 | 抜くと一番エネルギーが減る客から抜く |
| 壊す | 関連 | エネルギーで近い客をまとめて抜く（Shaw 型） |
| 壊す | NCR 除去 | NCR の停車を 1 つ消し，そこから飛んでいた客も抜く |
| 直す | 欲張り | 「トラックに入れる・既存の停車から往復・出撃」の中で一番安い所に入れる |
| 直す | 後悔 2 | 1 番目と 2 番目の差が大きい客から入れる |
| NCR | NCR 開設 | 候補を 1 つ経路に入れ，周りのドローン客を付け替える |
| NCR | 停車点の付け替え | トラックが寄る軽い客を 1 人ドローンに回し，近くの NCR に止まる（8.20.9.a で効いた形） |
| NCR | NCR 移動 | 使っている NCR を近くの候補に替える |

- 受理は SA，オペレータの重みは適応的に更新（Xiao の IALNS と同じ枠組み）
- 候補の集合は外から渡す（RQ2 の候補の作り方を後で差し替えられるように）
